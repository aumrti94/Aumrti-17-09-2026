## Blocking, cross-cutting finding: PHI leaving the boundary with no DPA and no purpose-specific consent

Applies to every function above except `ai-clinical-guidelines` (deterministic, never leaves the database).

- No Data Processing Agreement evidence exists in this repository for any of the six configured AI providers (Anthropic, OpenAI, Google, Perplexity, Azure, OpenRouter). `ai-icd-suggest`'s own source comment — "Ensure a Data Processing Agreement (DPA) covering PHI is in place before production use" — has sat unresolved since it was written.
- `supabase/functions/_shared/phi-redactor.ts` deliberately does not redact the outbound AI request payload, only logs and persisted audit records ("Do NOT apply to the actual AI request payload — clinical accuracy requires full context"). This means, for example, `ai-discharge-summary` sends a patient's real name, DOB, allergies, chronic conditions, full ward notes, labs, medications, radiology findings and ICD codes unredacted to whichever external model is configured. This is a deliberate, documented design choice for clinical accuracy, not an oversight — but it raises rather than lowers the compliance bar.
- No patient-level consent for "AI-assisted processing of my clinical data by a third-party AI model" exists anywhere in the codebase, separate from general treatment consent. `consent_form_templates`'s consent-type list has no `ai_processing` entry.
- `ai_usage_logs` has no `consent_id` column at all — there is no place to attach the consent reference CLAUDE.md's own rule requires ("AI inputs/outputs involving PHI must be logged with a consent reference").

Under DPDP Act 2023, a signed DPA (Section 8(2)) plus purpose-specific consent (Section 6) is the compliant path for this kind of processing — de-identification is not the only route DPDP provides for real-time operational (non-training) use. Aumrti currently has neither leg of that path in place.

**Governance sign-off is withheld on continued PHI flow through these functions until:**
1. A DPA is confirmed or signed with the active AI provider(s).
2. A distinct `ai_processing` consent artefact is added to `consent_form_templates` and captured before an AI feature touching PHI reaches the provider (Dr. Nalini will write the consent clause; Meera implements it in `consent_records`/`consent_form_templates`).
3. A `consent_id` column is added to `ai_usage_logs` and populated per call.

This is not a unilateral order to pause these features tonight — real hospitals are live on them, and the operational handling (a temporary consent banner plus a DPA fast-track, versus a feature pause) is a business-continuity decision requiring Preethi (CEO), Suresh (Regulatory), and Vikram (CTO) jointly. This record withholds governance sign-off and escalates the operational call to them; it does not decide it.

## SaMD / CDSCO exposure

No live CDSCO violation exists today — the 2024 draft SaMD guidance is not yet gazetted. The exposure is timing: an estimated 18-month runway to an expected 2026-27 mandate, against zero validation or failure-mode documentation for any of the eight functions today — exactly the evidence a future registration pathway (modelled on Medical Device Rules 2017, Rule 20A) would require retroactively. `ai-discharge-summary` and `ai-radiology-impression` are the two most likely to be pushed toward a higher SaMD class on review, given the discharge medication list's therapeutic-order character and the radiology impression's role as the interpretive conclusion other clinicians act on. Human-in-the-loop attestation is real mitigation for classification purposes but is not a substitute for the risk-documentation file itself — that file does not exist today for any of the eight functions.

## Plumbing sufficiency

The engineering session's auth/entitlement/error-handling fixes (KNOWN-BUG-198, -199, -200) are correct, necessary, and sufficient for what they addressed. An unauthenticated `ai-safety-guard` (KNOWN-BUG-199, now fixed) was itself a governance failure — anyone could have forged a safety-flag record against any hospital's audit trail. That pass explicitly and correctly declined to judge clinical content, prompt quality, or PHI/consent handling, and none of it satisfies any of the conditions in this record. It was never intended to, and this record states plainly that it does not.
