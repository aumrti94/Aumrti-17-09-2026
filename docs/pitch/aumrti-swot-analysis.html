01 — The analysis

Internal capability against external reality

The axes matter more than the four labels. Everything on the left column is an asset; everything on the right needs work. Everything on the top row is ours to fix before a pilot starts; everything on the bottom row must be planned around, because it will not move for us.

Internal

Strengths

8 verified

  • Indic-accented medical speech correction — consonant-skeleton phonetic bucketing tuned for Indian-English drug and diagnosis terms. "parasetamall" → PRSTML → paracetamol. Gated on Levenshtein similarity plus a safety check, so a bucket collision can never silently rewrite a drug name.

    _shared/medical-lexicon.ts — 635 LOC · parity-tested against its src/ twin

  • Deterministic safety net over every LLM output — allergy cross-reactivity, Schedule H/X controlled substances, per-dose ceilings, paediatric dosing flags. Pure and synchronous: it does not ask the model whether the model was right.

    _shared/safety-guard.ts — evaluateSafety() · CROSS_REACTIVE, DOSE_LIMITS tables

  • AI governed at a single chokepoint — provider keys never reach the browser; the entitlement gate is re-enforced server-side precisely because the client gate is treated as bypassable. Prompt registry, per-call cost attribution and prompt caching all sit at the same seam.

    supabase/functions/ai-proxy/index.ts — 668 LOC · _shared/ai-entitlement.ts

  • Safety AI is structurally exempt from cost control — drug-interaction, ADR, deterioration and critical-finding detection are never counted against a hospital's AI budget, and the budget prompts rather than blocks. A cap that could throttle those would be a safety mechanism wearing a billing costume.

    src/lib/aiFeatures.ts — SAFETY_AI_FEATURE_KEYS · src/lib/aiBudget.ts

  • PHI encryption built to DPDP §8(4) — AES-256-GCM envelope encryption, per-hospital data key wrapped by a Vault-held master key, and a separately derived HMAC key for searchable hashes so a search index can never decrypt the value it indexes.

    _shared/phi-crypto.ts · _shared/phi-redactor.ts · 13 encrypted column families

  • Clinical AI that shows its work — differentials surface supporting and contradicting features with confidence; the scores that drive escalation are guideline-derived and citable, not learned. NEWS2 to Royal College of Physicians, SOFA, APACHE II, NABH COP.6 nurse ratios.

    src/lib/news2.ts · acuityStaffing.ts · opd/DifferentialDiagnosisPanel.tsx

  • Doctor attestation is a database record, not a checkbox — AI clinical content carries a signed acceptance, who signed it, and whether it was edited first.

    migrations/…_ai_attestations.sql · components/ai/AIAttestationModal.tsx

  • India compliance is wired, not roadmapped — 10 ABDM functions built to NHA Integration Guide v3 headers with a production/sandbox switch, FHIR R4 across 8 resource types, plus PMJAY, CGHS, HCX, HMIS, IDSP and GST e-invoicing.

    _shared/abdm-auth.ts · fhir-r4-server/ · pmjay-* · hcx-* · gst-irn-generate/

Weaknesses

8 verified

  • Six tables are reachable from the browser with no row-level security Fix first — neither RLS enabled nor any policy, and no table-level revoke to compensate. Under Supabase's default grants that is cross-tenant exposure of insurance and financial configuration. One migration closes it.

    hospital_insurance_settings (15 call sites) · insurance_payment_reconciliation (8) · insurance_sla_log (2) · purchase_requisitions · rfqs · vendor_quotations

  • No trained models anywhere in the stack — every "predictor" is a language-model prompt over hand-engineered features. Defensible at pre-pilot stage, since there is no proprietary training data yet, but it is not machine learning and must not be described as such.

    No tensorflow/onnx/xgboost in package.json · clinicalPredictions.ts → callAI()

  • Test coverage is deep on six files, absent elsewhere — the 91% figure covers only the patient-safety and money-handling libraries, deliberately ratcheted so CI fails if they regress. Disciplined, but it is not project coverage and must never be quoted as such.

    vitest.config.ts — coverage.include lists 6 paths · 75 test files / 1,090 source files

  • Offline capability is infrastructure without coverage — the service worker, cache strategies and IndexedDB write queue are all real and correct, but exactly one screen enqueues through them. The claim "offline-first" outruns the wiring.

    src/lib/offlineQueue.ts — 1 enqueue() call site · consumed by NursingKardexTab only

  • Type safety erodes at the data boundary — 3,216 as any casts and 26 files with type checking switched off. In a system carrying prescriptions and claim amounts, each one is a place the compiler has stopped helping.

    3,216 casts in src/ (3,376 incl. edge functions) · 26 files with @ts-nocheck

  • Bus factor of one — a single contributor across three git identities. Snapshot-style commits also mean version history understates the real build effort and weakens IP provenance, which is exactly what diligence looks at.

    git shortlog — aumrti94 / Yeswanth Gottumukkala / yeswanthvarma94

  • Nine dependency vulnerabilities outstanding — five high, four moderate. Low effort to clear and it should be cleared before any security questionnaire.

    npm audit — 5 high, 4 moderate, 0 critical

  • No live deployment, so no clinical evidence — every efficiency claim is currently architectural. Time-saved, discharge turnaround and denial-rate numbers cannot exist until a hospital runs it, which is precisely the ask.

    Stated openly in the existing deck and outreach letter — keep it stated

Threats

6

  • Compliance is architectural until it is certified Gate — ABDM readiness cannot be marketed as ABDM compliance before milestone certification. Language discipline here protects credibility with government buyers.

    abdm-auth.ts — degrades to sandbox-format-only when credentials absent

  • Medico-legal exposure on AI clinical output — India has no settled liability framework for algorithmic clinical recommendations. Attestation covers roughly seven of about sixty live AI features; extending it across all clinical-facing features is the mitigation.

    ai_attestations CHECK constraint lists 7 features · AIAttestationModal at 7 sites

  • Incumbent HIS and EHR vendors bolting on AI — they arrive with installed base and hospital relationships. They do not arrive with Indic-accented medical ASR correction or native PMJAY, HCX and NABH workflows, which is where the defence sits.

    Defence: medical-lexicon.ts · pmjay-* · hcx-* · nabh modules

  • Provider dependency and currency mismatch — inference is billed in USD and priced to hospitals in INR. Multi-provider routing limits lock-in, but margin remains sensitive to both model pricing and the exchange rate.

    ai-proxy COST_PER_1K in USD · _shared/platform-rate.ts getUsdToInr()

  • DPDP enforcement and CERT-In incident timelines — six-hour breach reporting and consent-manager obligations are operational commitments, not code. Encryption and PHI access auditing are in place; the response process is not yet written.

    phi_access_audit table exists · no documented incident-response runbook

  • A residency policy shift could strand routing choices — if in-country inference becomes mandatory for health data, the Azure India Central path survives and the others do not. The abstraction is the hedge; it should stay maintained.

    aiProvider.ts — 7 providers behind one callAI() interface

03 — Boundaries

What we do not claim

These four were in an earlier draft of this analysis. Each was removed because the codebase does not support it. They are listed rather than deleted, because a reviewer who finds them independently should find we found them first.

Not "advanced machine learning"
There is no model training, no inference runtime, no learned weights. Forecasting and risk scoring are language-model prompts over engineered features. The clinical scores that trigger escalation are deterministic and guideline-derived, which we consider the safer choice at this stage — but neither is ML.
Not "autonomous resource allocation"
Nothing in the system allocates a bed, a theatre slot or a nurse without a human acting. Nurse-to-patient requirements are computed from NABH COP.6 ratios against live NEWS2 acuity and presented for a decision. That is decision support, and we describe it that way.
Not "91% test coverage"
That figure belongs to six deliberately chosen files — drug safety, clinical calculators, billing totals, GST rules, currency, quality indicators — held under ratcheted CI floors so a regression fails the build. It is a real engineering discipline and a real limit, and conflating it with project coverage would be a misstatement.
Not "proven in production"
Zero live hospital deployments. Every operational benefit in this document is architectural until a pilot measures it. That measurement is what we are asking RTIH for, and overstating it now would waste the pilot it is meant to win.
