====================

CRITICAL FINDING: The plan editor (PlansManagerPage) and the subscription gate (useSubscriptionConfig) use DIFFERENT module key sets.

1. PlansManagerPage.tsx (Plan Editor)
   - File: d:\Aumrti 06-06-2026\src\pages\platform\PlansManagerPage.tsx
   - Line 44-62: Defines ROUTE_KEY with only 17 unique routes
   - Line 63: ALL_KEYS = [...new Set(Object.values(ROUTE_KEY))] = 17 unique keys
   - Modules shown in UI: ~18 (those in ROUTE_KEY that map from ALL_MODULES)
   - Saves to plan_features: module_key values from ALL_KEYS only
   - Problem: HARDCODED, incomplete ROUTE_KEY is missing 50 of the 67 modules

DIVERGENCE SOURCE:
=================

PlansManagerPage and HospitalDetailPage both HARDCODE ROUTE_KEY (lines 44-62 and 86-104) as a static, incomplete map.
useSubscriptionConfig uses ROUTE_TO_MODULE_KEY (lines 71-130) which is comprehensive.

The two are derived from DIFFERENT SOURCES:
- Plan Editor: Hardcoded constants in component files
- Gate: More complete map in hook file (still hardcoded but more comprehensive)

IMPACT:
=======

When a plan is saved with (say) 18 modules enabled, the plan_features table gets ~18 rows with module_keys.
When useSubscriptionConfig queries plan_features, it loads those ~18 rows into planMap.
Then it loops through CANONICAL_MODULE_KEYS (56 keys) at line 211.
For ~38 missing keys (e.g., /billing, /ipd, /emergency, /nursing, /radiology, /lab, /hr, /quality, /insurance, /payments, /telemedicine, /pmjay, /assets, /dialysis, /oncology, /mortuary, /vaccination, /ambulance, /dental, /ayush, /ivf, /neonatal, /mrd, /biomedical, /hmis, /dietetics, /lms, /abdm, /patient_portal, /patient_relations, /analytics, /hod_dashboard, /settings, etc.):
- planMap.get(key) is undefined
- Line 218: planMap.size > 0 and planMap.get(key) is not true → key is NOT added to enabledModules
- Hospital loses access to ~38 modules even if CEO assigned a plan

THE 56 vs 18 COUNT:
==================

Users see "18/56" because:
- Line 323 (PlansManagerPage): enabledCount / ALL_KEYS.length
- ALL_KEYS.length = 17-18 unique values from the incomplete ROUTE_KEY hardcoded in the plan editor
- The denominator should be 56 (CANONICAL_MODULE_KEYS length) but is instead 17-18
- The numerator counts only modules the plan editor can edit (the broken ones in its ROUTE_KEY)
